商品图库接口文档

提供商品信息，调用一个图片查询接口，就能拿到可用图片的信息，再按授权方式取图。 图片列表使用 GET /api/v1/images；需要型号参数时，再按图片 ID 获取详情。

能做什么

按商品信息查询图库中的图片，供业务系统程序化调用。

传入一个或多个筛选条件，列表接口返回同时满足这些条件的图片记录。每条记录包含图片 ID、品牌、型号、颜色、尺寸及图片地址；再按图片 ID 调详情接口，可获取该型号的参数名和值。

适合用在商品上架、素材整理、批量导出这类需要自动取图的流程里。

支持的筛选维度

品类 手机 / 平板电脑 / 智能手表 / 笔记本

品牌 例如 Apple、华为、小米

型号 支持名称模糊查询或精确型号筛选

颜色 例如 蓝色、冰川蓝色

通过列表和详情完成接入

先按商品条件查询图片列表；需要单张图片完整信息或型号参数时，再用图片 ID 查询详情。

i

业务视图按品类与治理状态过滤素材：手机仅返回 A 级图片；非手机不返回受限素材，候选素材仅可预览、不能取原图或下载。需要登录后才能调用，具体见 怎么拿到图片。

怎么调用

先登录拿会话，再用一次 GET 请求查询。

  1. 登录，拿到会话 Cookie

    图库使用账号登录，没有 API Key。登录成功后服务端下发会话 Cookie，后续请求带上它即可。

    curl 
    curl -c cookies.txt -X POST https://picsystem.changziqi.com/login \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "username=你的账号" \
  --data-urlencode "password=你的口令"

  2. 用商品信息查询图片

    筛选条件可以只传一项，也可以组合；多个筛选条件取交集。下面查「手机 / Apple / iPhone 14 / 蓝色」：

    curl 
    curl -b cookies.txt \
  "https://picsystem.changziqi.com/api/v1/images?category=phone&brand=Apple&model=iPhone%2014&color=%E8%93%9D%E8%89%B2&limit=10"
    python 
    import requests                     # pip install requests

BASE = "https://picsystem.changziqi.com"
s = requests.Session()
s.post(f"{BASE}/login",
       data={"username": "你的账号", "password": "你的口令"},
       allow_redirects=False)        # 返回 303 即登录成功

r = s.get(f"{BASE}/api/v1/images",
          params={"category": "phone", "brand": "Apple", "model": "iPhone 14", "color": "蓝色", "limit": 10})
r.raise_for_status()
data = r.json()
print("共", data["total"], "张")

for item in data["items"]:
    print(item["id"], item["display_color"], item["width"], "x", item["height"])

可用的查询参数

全部可选；只写你确定的那几个就够了。

参数填什么说明示例
category品类默认 phone。支持 phone、tablet、watch、laptop；all 表示全部品类。phone
q关键词在品牌、标准/目录型号及相关颜色字段中模糊搜索。关键词内部命中任一字段即可，再与其他条件取交集。iPhone 14
group品牌组可用 xiaomi、vivo、oppo。可与 brand 组合，组合时需同时满足。xiaomi
brand品牌按图库展示品牌精确匹配。Apple
model型号关键词在标准型号名称中做包含匹配；例如传 iPhone 14 会命中名称中包含该字符串的型号。iPhone 14
model_exact完整型号名称精确匹配完整型号；默认来源为标准型号。苹果 iPhone 16 Plus
model_source型号来源与 model_exact 配合：standard 标准型号（默认），directory 未标准化目录型号。standard
color颜色精确匹配；手机使用展示/标准颜色，非手机使用 Gaia 参考色。白色
official_color品牌官方色非手机官方颜色精确匹配；和 color 是不同字段。手机传此参数不会命中图片。月神灰
status匹配状态按图片匹配状态精确筛选。已匹配
asset_kind素材类型非手机品类可选 white、marketing、detail；不传默认只查白底商品图。white
publish_state发布状态用于非手机品类状态筛选。公开业务查询不可检索 restricted 受限素材。published
view数据视图仅有复核权限的账号传 review 才进入复核视图；普通账号仍按业务可见范围返回。review
limit每页条数1～200，默认 60。50
offset起始偏移从筛选结果的第几条开始，默认 0。0

传部分条件后会返回什么？

返回所有满足已传条件的图片记录，但每次响应只含当前一页。不同筛选参数之间按 AND 取交集；例如只传 brand=Apple，会返回可见范围内 Apple 的图片；传 brand=Apple&model=iPhone 14，只返回同时属于 Apple 且型号名包含 iPhone 14 的图片。只有 q 自身会在品牌、型号、颜色等字段之间按 OR 搜索。

响应中的 total 是满足筛选条件的总记录数，不受分页影响；items 是本页。默认每页 60 条，最多 200 条。要取全量结果，就重复请求并将 offset 每次增加 limit，直到取满 total。不传筛选项仍会分页返回结果；category 默认是 phone，业务视图只返回当前可用范围内的图片。

型号参数

型号参数按 Gaia model_id 关联到标准手机型号。同一型号的不同颜色图片共享该型号参数，因此参数不重复放进列表里的每张图片记录；需要参数时，先从列表取得图片 id，再请求详情接口 GET /api/v1/images/{id}。

详情响应新增 model_params_count（参数项数）和 model_params（数组，每项有 name、value）。参数数组按来源顺序返回。未匹配到参数的型号返回空数组和数量 0；当前参数数据仅覆盖已匹配的手机型号，非手机返回空数组。

参数内容来自随应用发布的参数快照，不是每次请求时实时查询外部来源。参数更新后需随应用资源发布；缺失参数不会影响图片列表筛选和图片详情的其他字段。

json
{
  "id": "图片ID",
  "model_id": "4114",
  "model_name": "vivo X Fold",
  "model_params_count": 62,
  "model_params": [
    {"name": "参数名称", "value": "参数值"},
    {"name": "参数名称", "value": "参数值"}
  ]
}

返回什么

列表返回 JSON，每张图片一条摘要记录；完整型号参数请用图片 ID 调用详情接口。下面是列表响应结构示例。

json 
{
  "total": 1,
  "limit": 10,
  "offset": 0,
  "items": [
    {
      "id": "img_25807e9a7151",
      "display_brand": "Apple",
      "model_name": "苹果 iPhone 14",
      "model_id": "12345",
      "standard_color": "蓝色",
      "display_color": "蓝色",
      "format": "JPEG",
      "width": 1600,
      "height": 1600,
      "size_bytes": 408896,
      "can_view_original": true,
      "can_download": true,
      "file_url": "/api/v1/images/img_25807e9a7151/file",
      "thumb_url": "/api/v1/images/img_25807e9a7151/file?w=320",
      "download_url": "/api/v1/images/img_25807e9a7151/download"
    }
  ]
}

业务需要关心的字段

字段含义
total 符合条件的图片总数，用于判断要不要翻页。
items[].id 图片 ID。取图、下载时用它拼地址。
items[].display_brand 品牌，例如 Apple。
items[].model_name / model_id 型号名称及 Gaia 型号 ID。model_id 用于核对型号及关联型号参数。
items[].standard_color 已确认的标准颜色；与展示颜色分开提供，供精确组合核对。
items[].display_color 颜色，例如 蓝色。
items[].format / width / height / size_bytes 格式、像素宽高、文件大小（字节），用于判断素材是否满足投放要求。
items[].file_url 取原图的相对地址。拼上站点域名即可请求。
items[].thumb_url 缩略图地址（宽 320 的 WebP），适合列表展示。
items[].download_url 下载地址，返回带规范文件名的附件。
items[].can_view_original / can_download 这张图当前是否允许看原图、是否允许下载。为 false 时只可用缩略图。

接口不返回服务器本地路径，也不会返回内部治理字段；取图请一律使用上面三个 url 字段。

怎么拿到图片

查询接口返回的是图片信息，不是图片文件本身 —— 取图需要再发起一次请求。

!

这一点必须说清楚：GET /api/v1/images 只返回 JSON（ application/json），不会直接返回图片字节。要拿到图，用返回里的 file_url 或 download_url 再请求一次，并且同样要带登录会话。

方式一：取原图（用于预览、后续处理）

请求 file_url，返回图片本身。加 ?w=320 返回缩略图。

curl 
curl -b cookies.txt -o image.jpg \
  "https://picsystem.changziqi.com/api/v1/images/img_25807e9a7151/file"

方式二：下载（用于交付、归档）

请求 download_url，服务端会带上规范文件名。

curl 
curl -b cookies.txt -OJ \
  "https://picsystem.changziqi.com/api/v1/images/img_25807e9a7151/download"

完整流程（查询 → 取图）

python 
import requests

BASE = "https://picsystem.changziqi.com"
s = requests.Session()
s.post(f"{BASE}/login", data={"username": "你的账号", "password": "你的口令"},
       allow_redirects=False)

items = s.get(f"{BASE}/api/v1/images",
              params={"brand": "Apple", "model": "iPhone 14", "limit": 1}).json()["items"]

first = items[0]
if not first["can_download"]:
    raise SystemExit("这张图当前不允许下载，只能使用缩略图")

img = s.get(BASE + first["download_url"])
img.raise_for_status()
open("image.jpg", "wb").write(img.content)
print("已保存", first["display_brand"], first["model_name"], first["display_color"])

权限与访问范围

登录方式：账号 + 口令，服务端下发会话 Cookie（HttpOnly）。目前没有 API Key， 也不支持 Bearer 令牌；未登录访问会返回 401。

适用范围：适合人工登录后的操作，以及同一会话内的脚本和内部工具； 暂不适合其他系统用固定凭据长期无人值守对接 —— 这类能力需要另行立项补齐。

素材范围：只返回已确认可用的素材；未确认、已停用或受限的素材不通过本接口开放。 can_view_original / can_download 为 false 时，说明该素材当前只允许缩略图预览。
