# 前端模块独立发布

本文仅说明前端发布机制。登录和公共外壳由网关提供；后端已有独立服务拆分工作区，具体边界与未完成事项见 `../项目日志.md`。

## 一次性基础改造

应用启动时读取 `/app/frontend-modules`，经登录保护的 `/frontend-modules/manifest.json` 发现模块，并按版本 URL 加载模块 HTML、CSS 和 JavaScript。Compose 将宿主机 `./frontend-modules` 以只读方式挂入容器。

这部分应用外壳和通用资源路由需要一次常规应用发布。它完成后，后续只发模块资源，不再构建或替换图库容器。

## 模块包

每个版本目录包含：

```text
module.json
index.html
module.js       # 必须 export function mount(root, context)
module.css
```

`module.json` 字段：`id`、`version`、`title`、`subtitle`、`nav_label`、`icon`、`order`。模块脚本只操作传入的 `root`，不要依赖页面全局 ID 或覆盖其它模块的全局变量。API 调用使用同源 `/api/...`，继续由现有 Session 认证保护。

SPA 视图模块默认 `surface: "view"`（可省略）。独立完整页面可设 `surface: "route"`：它仍走同一个版本目录和受保护资源路由，但不自动插入主页面导航；需要由应用中的稳定入口（例如 `/docs`）解析当前版本后跳转。完整页面的 HTML 用相对路径加载同目录 `module.css` 与 `module.js`。

覆盖监控是首个拆出的模块，源文件在 `frontend-modules/coverage/versions/1.0.0/`。版本目录发布后不可修改；每次更新使用新版本号。

## 发布与回滚

先把模块版本包放到服务器可读的临时目录，再在服务器执行：

```bash
deploy/publish-frontend-module.sh coverage 1.0.1 /path/to/coverage-package 1.0.0
```

脚本逐模块加锁、校验清单、复制到新版本目录，然后用原子符号链接切换 `current`。不同模块有各自的锁，可以并行发版；同一模块更新会串行执行，版本号不能覆盖。发布后重新打开页面即可获取新清单，新 JS/CSS 使用不可变版本 URL，浏览器缓存不会把旧模块文件和新清单混用。

脚本会打印回滚命令。回滚只把对应模块的 `current` 链接切回旧版本，不触碰其它模块或图库服务。

## 边界

- 此机制拆的是前端功能资源，不拆业务 API，也不新增微服务。
- 更新单个模块：不需要 Docker build、Compose up、Nginx 变更或服务重启。
- 修改登录、共享导航/外壳、静态路由或 API 合同：仍需要应用版本发布。
- 模块清单和资源沿用图库登录态；未登录访问返回 401。
- 线上启用前须先部署一次性基础改造，并按项目要求做真实登录态页面验收。

## 协作发布基线检查（2026-11-22 本地增强）

第四个参数是开发所依据的目标模块当前版本；首次发布填写 `none`。脚本在模块锁内比较实际版本，不一致则拒绝发布。不能只改参数强行通过：先核对并整合期间发布的改动。旧三参数命令会被拒绝；服务器尚未安装本次增强，不能视为已有线上保护。

回滚也应持有同模块锁并核对当前版本。脚本打印的旧回滚命令不是并发安全工具，协作期须暂停同模块发布后由发布负责人核对执行。此增强不替代生产真实登录态验收。
